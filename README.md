# Демо-сайт центра слухопротезирования

**Сайт открыт:** https://froghoppingamongtulips.github.io/centr-sluha-site/

Ссылку видит только тот, кому её дали: страница закрыта от поисковиков (`robots.txt` и `noindex`), в Яндексе и Google не появится.

Многостраничный сайт на **React + Vite**: витрина центра слуха с каталогом аппаратов, услугами, центрами, статьями и формами заявки.

Контент демонстрационный:

- модели аппаратов, характеристики, цены и **фотографии** взяты из обзора [expertology.ru «13 лучших слуховых аппаратов»](https://expertology.ru/13-luchshikh-slukhovykh-apparatov/) — для боевого сайта нужны свои снимки или разрешение правообладателя;
- набор разделов, услуг и блоков — по структуре [ssluha.ru](https://www.ssluha.ru/);
- контакты настоящие: +7 (913) 821-73-47, kostochkodebildmitriy@gmail.ru, Томск, Иркутский тракт, 33 (Октябрьский район);
- название центра, имена врачей, отзывы и цены на услуги **вымышлены**;
- лицензий, сертификатов и реквизитов на сайте нет — только предупреждение «имеются противопоказания»;
- фото аппаратов лежат в `public/img/`, остальные снимки — чёрные блоки (`src/components/Ph.jsx`), логотип — SVG в `src/components/Logo.jsx`.

Чтобы поставить фото врача: положите файл в `public/img/` и пропишите путь в поле `img` нужного врача в `DOCTORS` (`src/data/site.js`), например `img: '/img/doctor.jpg'`. Пока фото нет — на их месте чёрные блоки.

Весь текст и все цифры правятся в одном файле — `src/data/site.js`.

## Структура сайта

| Раздел | Маршрут | Что внутри |
|---|---|---|
| Главная | `/` | снимок во всю ширину и карточка с рассказом о центре — как на сайте-образце. Разделы, адреса и контакты — в меню и подвале |
| О центре | `/about` | как проходит подбор, цифры, почему к нам, этапы, бренды, частые вопросы |
| Каталог | `/catalog`, `/catalog?cat=<slug>` | чипы категорий, фильтры, сортировка, карточки, пагинация, текст «как выбрать» |
| Карточка | `/catalog/:slug` | галерея, цена и старая цена, условия, кнопки записи и звонка, «в корзину», табы описание/характеристики/условия, форма, похожие |
| Акции | `/promo` | рассрочка, скидка на второй аппарат, подарок; форма вопроса |
| Центры | `/locations`, `/locations/:slug` | поиск по адресу, карта, карточки; страница центра: адрес, метро, график, «как добраться», врачи, форма |
| Информация | `/news`, `/news?type=news\|article`, `/news/:slug` | новости и полезные статьи в одной ленте, статья с врезками и формой вопроса |
| Корзина | `/cart` | отложенные модели для примерки, форма записи |
| Контакты | `/contacts` | телефон, почта, адреса, карта, график, три формы в табах |
| Документы | `/privacy`, `/consent` | политика и согласие на обработку данных |
| 404 | остальное | возврат на главную и быстрые ссылки |

Сквозные элементы: верхняя полоса, поиск, выпадающие категории в меню, корзина, липкие кнопки записи/звонка/вопроса справа, кнопка «наверх», подвал с картой сайта и мессенджерами.

## Формы

`src/components/RequestForm.jsx` — три варианта:

- `visit` — запись: имя, телефон, цель визита, дата, время, комментарий;
- `ask` — вопрос: имя, телефон, почта, текст;
- `call` — обратный звонок: имя, телефон, удобное время.

Открываются на страницах и в модальном окне: `useRequestForm()` → `openForm('call' | 'visit' | 'ask', slug?)`.

Сервера у сайта нет, поэтому форма не делает вид, что отправила заявку: она собирает
текст обращения и предлагает отправить его сообщением на рабочий номер, письмом или
позвонить. Когда появится CRM или почтовый сервис, в `RequestForm.jsx` останется
один запрос вместо трёх ссылок.

## Корзина

`src/components/CartContext.jsx` — список отложенных моделей без количеств: это не интернет-магазин, а подбор моделей к примерке. В шапке при непустом списке горит точка.

## Запуск

```bash
npm install
npm run dev      # http://localhost:5173
npm run build    # сборка в dist/
npm run preview  # просмотр сборки
npm test         # прогон проверок по собранной версии
npm run deploy   # собрать и обновить опубликованный сайт
```

## Панель управления

Содержимое сайта может приходить из панели (Directus): товары, услуги, акции,
новости, центры, контакты — и туда же падают заявки с форм.

- клиент панели: `src/lib/panel.js`, общий источник данных: `src/components/ContentContext.jsx`;
- адрес панели задаётся в `.env.local`: `VITE_PANEL_URL=http://localhost:8055`;
- переменная не задана — сайт работает на встроенных данных из `src/data/site.js`,
  а заявки предлагает отправить сообщением или письмом.

Панель — в папке `panel/` рядом с сайтом (в репозиторий не входит): Directus 11 на SQLite
со своим Node 22 внутри, на компьютер ничего ставить не нужно.

- запуск — `panel/ЗАПУСК ПАНЕЛИ.cmd`, адрес http://localhost:8055;
- логины и пароли — в `panel/.env`: технический администратор и учётка владельца центра;
- разделы, права и перенос содержимого сайта — `panel/scripts/setup.mjs`, повторный запуск безопасен;
- инструкция для владельца — `panel/ПАМЯТКА.md`.

## Проверки

`tests/site.spec.js` — проверки основных сценариев: слайдер, каталог с фильтром и страницами,
счётчики разделов по реальным товарам, карточка товара, корзина, формы (маска телефона,
заявка помнит выбранный товар), акции, статьи целиком, поиск, сортировка и фильтр по цене,
карта, мета-теги и адреса превью, мобильная вёрстка и доступность. Количество слайдов, акций
и товаров тесты берут из данных сайта, поэтому новая акция их не ломает. Гоняются по собранной
версии на локальном сервере; `npm test` работает и на Windows.

При каждом пуше те же тесты выполняются в GitHub Actions (`.github/workflows/check.yml`).

## Публикация

Отдельной команды не нужно: после `git push` в ветку `main` GitHub сам собирает проект
и выкладывает его на Pages (`.github/workflows/deploy.yml`). Обновление появляется
на сайте через две-три минуты.

Собрать то же самое у себя, чтобы посмотреть перед отправкой, — `npm run deploy`,
результат ляжет в `dist/`.

Панель управления (папка `panel/`) в репозиторий не попадает: в ней база с заявками,
пароли и загруженные файлы.

Сайт закрыт от индексации: `public/robots.txt` запрещает обход, в `index.html` стоит `noindex`.
Пароля на входе нет — доступ у всех, кому дали ссылку.

Прямые ссылки на внутренние страницы работают через `404.html`: GitHub Pages отдаёт её вместо
несуществующего файла, приложение читает адрес и открывает нужную страницу.
